# 案例研究：工业表面缺陷检测系统

一条产线上做的表面缺陷检测系统，已经上线跑起来了。它把原来的人工目检换掉了；第二版重做了一部分架构，让新产品线靠配置就能加进来，不用从零重建。

> 🌐 英文版 / English version: [industrial-vision-inspection.md](industrial-vision-inspection.md)

---

## 背景

这条线原来靠人看零件表面有没有缺陷。量和品种一多，结果就开始飘，缺陷也往下游漏，而且查了什么、哪里不合格，完全没有记录。

后来发现，同一拨人还要服务好几条产品线、好几个客户。每来一条新线，基本就是把系统重写一遍。第二版就是为了这个做的。

---

## 问题

- 人工目检不稳定，也没法审计。
- 查没查、哪里不合格，没有结构化记录。
- 经验都在操作员脑子里。
- 每加一条产品线，就是一次大动干戈的重建。

---

## 约束

| 约束 | 细节 |
|------|------|
| 时延 | 推理得跟住产线速度，逐相机、实时 |
| 环境 | 车间：粉尘、振动、光照乱变 |
| 离线 | 有些工位没常连网，个别还是物理隔离 |
| 可维护 | 操作员天天用，工程师很少到现场 |
| 多样性 | 多条线，相机/工位/角色各不相同 |

---

## 方案

分层后端 + Vue 前端 + 面向车间的 PySide6 桌面壳：

```
┌──────────┐   MVS SDK  ┌──────────────┐   ┌────────────┐   ┌──────────────┐
│ Cameras  │──────────►│ Imaging /    │──►│ Model      │──►│ FastAPI +    │
│ (Hikvision│           │ Preprocess   │   │ (Anomalib /│   │ Vue3 dash.   │
│  line/area)│          │ (OpenCV)     │   │  YOLO)     │   │ + PySide6    │
└──────────┘           └──────────────┘   └────────────┘   │  desktop shell│
                                                           └──────┬───────┘
                                                       results API │ SSE
                                                           ┌──────▼───────┐
                                                           │ Review queue │
                                                           │ + audit log  │
                                                           └──────────────┘
```

- **采集**：海康 MVS SDK 驱动线阵/面阵相机，按角色（top/bottom/axis）采集。
- **预处理**：OpenCV 流水线，缩放、光照归一、ROI/掩模。
- **模型**：Anomalib PatchCore 做无监督检测（几乎不用标注缺陷），YOLO 做有监督（计划中）。
- **后端**：FastAPI，拆成 routes / services / schemas / repositories / models。接口干净：`POST /api/detection/start`、`GET /web`，还有 camera / model / recipes / system_settings / users 几个模块。
- **前端**：Vue3 看板，实时状态、缺陷计数、复核队列。
- **桌面壳**：PySide6（QWebEngineView）套着同一套 Vue UI，用于车间控制和离线运行。
- **审计**：每条结果记图像哈希、时间戳、模型版本。

### 第二版：做成可配置

第一版每条产品线都写死了。重做的时候改了思路，用几个基本维度去拼系统：

```
相机 = 成像类型(线阵/面阵) × 品牌型号(海康…) × 实例
Stage = 协议(Modbus RTU) × 型号(寄存器映射 + 职责) × 实例
角色(被检面) = 业务概念，随便命名(axis/top/bottom/side/…)
流程 = 配置出来的一段序列(进料 / 位姿 / 拍照 / 结果 / 换料)
```

加一条产品线，现在就是写一份配置（相机规格、工位规格、角色集合），不用动代码。

如果拿这个去跟新客户聊，我会先讲这段——它说明系统能跨线扩展，不用重写。

---

## 关键技术决策

### 1. 用 Anomalib PatchCore，不上全监督模型
我们没有大量标注好的缺陷样本，真要去攒一套又慢又贵。PatchCore 几乎不用标注就能检出"不正常"，所以能先上线，再按线慢慢调。

### 2. 车间用 PySide6 桌面壳，不是纯浏览器
车间要离线跑、要低时延紧耦合设备控制。把 Web UI 套进桌面壳，就能做到，还不用依赖浏览器和 IT。

### 3. 配置优先于按线写码
以前每条线克隆改一遍。改成用数据驱动组合之后，加线变成一次配置改动，而不是两周重建。这对多客户下的利润和可靠性都更稳。

### 4. 分层 FastAPI
逻辑不堆在路由里（routes / services / repositories 分开），模型和流水线就能换，前端和对接方也拿到一份干净的 API 契约（OpenAPI）。

---

## 我的收获

模型从来不是难点。难的是光照、触发、相机和工位怎么拼到一起。还有，结果只有车间里的人信了才算数。按"配置优于代码"来设计，才是系统能跨客户用起来的原因。
